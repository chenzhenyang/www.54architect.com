## 从 Copilot 到智能体：AI 编程简史

AI 编程智能体的历史始于人们还认真把它们称为"智能体"之前。2017 年，《Attention Is All You Need》论文引入了 Transformer 架构，这是现代大语言模型得以实现的基石。

2020 年，CodeBERT 将这一基础更靠近了软件开发，展示了自然语言和编程语言可以在一个统一的预训练系统中被一起学习，用于代码搜索和文档生成等任务。

这些还不是现代意义上的智能体。它们不会打开文件、运行测试，也不会在开发环境中行动。但它们确立了一个使一切成为可能的前提：代码可以被建模为语言，而语言模型可以学习软件如何被编写、解释和转换的有用表示。

到了 2021 年，这条研究路线已经成熟为实用、可测试的代码生成。Codex（2021）描述了一个在公开可用代码上微调的 GPT 模型，并通过 HumanEval 进行评估。GitHub 于 2021 年 6 月 29 日宣布了 Copilot，而 Codex 论文随后在 7 月 7 日发布，明确指出一个独立的 Codex 生产版本为 Copilot 提供动力。这个细节很重要，因为它标志着 LLM 从研究工件跨越到主流开发者产品的桥梁。

### Copilot 让 AI 编程变得自然

当 Copilot 到来时，它做了一件在历史上比"写代码"更重要的事：它让 AI 感觉像是编程行为的自然组成部分。GitHub 将 Copilot 描述为一个 AI 结对程序员，可以从周围的代码中提取上下文，并在编辑器内建议整行甚至整个函数。

这听起来现在很普通，但在 2021 年，这是一个真正的界面突破。代码生成不再停留在研究演示中，而是开始出现在编辑表面上，在那里延迟、相关性和开发者信任比抽象基准分数更重要。

这就是为什么 Copilot 的成就超越了传统的自动补全工具。它的意义不仅仅在于模型质量，而在于将模型直接放入编写软件的工作流中这一产品决策。

GitHub 后来的研究发现，Copilot 用户完成任务更快，并报告节省了脑力。换句话说，Copilot 不仅证明了模型可以输出代码，还证明了 AI 辅助可以改变软件开发的过程。

### 自动补全之后是意图理解

下一个重要信号出现在 2022 年，而且并非来自编辑器。DeepMind 的 AlphaCode 表明，更难的编程问题通常需要超越优雅的一次性生成的东西。AlphaCode 生成大量候选程序， aggressively 过滤它们，并依赖程序行为而非表面流畅度。在竞技编程中，它达到了中水平参赛者的水平。

从历史角度看，AlphaCode 之所以重要，是因为它预示了一个后来编码智能体不断依赖的原则：困难的软件任务往往是搜索问题，而不仅仅是语言问题。

同年晚些时候，ChatGPT 使与模型的对话式交互成为主流，而 InstructGTO 已经展示了为什么这很重要：被调优以遵循用户意图的模型比仅仅继续文本的模型更有用。

2023 年 3 月，GitHub Copilot X 将这一转变直接带入软件开发，带来了聊天、拉取请求辅助、文档帮助和 GPT-4 集成。从那时起，开发者与机器之间的关系发生了变化。你不再需要等待正确的补全出现。

你可以解释你想要什么、请求重构、请求测试，或者让系统解释不熟悉的代码。

### 对话不够，助手需要看到仓库

一旦编码 AI 变得可对话，一个新的瓶颈出现了：上下文。聊天的好坏取决于它能检索到多少关于眼前项目的信息。GitHub 的仓库索引文档明确地展示了这一转变。

索引在后台运行，一旦索引存在，Copilot Chat 就能回答关于 GitHub 和 VS Code 中仓库的问题。这是编码 AI 不再表现得像一个聪明的陌生人，而开始更像一个至少读过代码库的同事的时刻。

同时，开放代码模型开始更直接地适应程序员实际编辑的方式。SantaCoder 强调了中间填充生成。StarCoder 以更广泛的语言覆盖和更长的上下文推进了开放模型的前沿。Code Llama 强调了填充和更大的输入窗口。

这些细节之所以重要，是因为真正的开发者很少从左到右在空白页面上编写代码。他们在现有系统中插入、修补、重构、打桩和修复。训练目标开始与软件工作的机制相匹配。

### 智能体是能够行动的模型

这就是现代"智能体"含义开始凝结的地方。当编码模型能够做的不仅仅是生成看似合理的代码时，它就变成了编码智能体。它必须检查文件、调用工具、运行命令、观察失败，然后继续。

ReAct 论文为领域提供了一个清晰的推理与行动交织的概念模板，而 OpenAI 的函数调用使工具使用成为实际的产品和 API 模式。Together，它们将领域从被动生成转向了与环境的闭环交互。

这一想法很快变得具体。SWE-agent 论文的作者认为，语言模型智能体需要自己的"智能体计算机界面"来导航仓库、编辑文件和执行程序。

Devin 将 shell、编辑器和浏览器打包到一个沙盒计算环境中。OpenHands 将同样的论点变成了一个更开放和可组合的堆栈，可以在本地、终端或 CI/CD 工作流中运行。在每种情况下，突破不仅仅是更好的代码生成，而是采取行动、检查结果并再次尝试的能力。

### 基准测试不再要求函数，而是要求工作

基准测试在缩影中讲述了历史。2021 年，HumanEval 衡量模型能否从文档字符串中合成正确的函数。到 2023 年，SWE-bench 论文的作者询问系统能否在真实仓库中解决真实的 GitHub 问题。这一转变是巨大的。

领域不再问模型是否能产生看似胜任的代码，而是开始问系统是否能在真实约束下实际完成软件任务。

然后标准再次提高。SWE-bench Verified 引入了一个人工验证的子集，用于更可靠的评估。LiveCodeBench 专注于无污染评估，并明确将目标扩展到包括自我修复、代码执行和测试输出预测。

Terminal-Bench 更接近现实，通过衡量在困难的、真实的命令行任务上的表现。评估不再奖励看似合理的代码，而是开始奖励能够完成真实工作的系统。

### 后台智能体时代

到 2025 年，这个类别再次改变了形状。截至 2026 年初，GitHub 文档化了两种互补的智能体体验。在 VS Code 中，你可以描述你想构建什么，让智能体规划、实现和验证整个项目的变更。在 GitHub 本身中，Copilot 编码智能体作为拉取请求工作流的一部分在后台工作。你分配工作，它进行变更、打开拉取请求，然后请求审查。助手不再需要在光标处等待。智能体可以接受任务并带着工作成果回来。

其他平台也趋同于相同的模式。OpenAI Codex 产品在 2025 年作为软件智能体重新引入，用于更长运行时间的任务，而 Google 的 Jules 明确被定位为实验性编码智能体，集成到 GitHub 中，自主工作，并可以在安全的云虚拟机中打开带有可运行代码和测试结果的拉取请求。云沙盒成为了后台编码智能体的自然栖息地。

### 终端和编辑器成为控制面板

本地界面并行演进。Claude Code 被 Anthropic 描述为一个智能体编码工具，可以读取你的代码库、编辑文件、运行命令，并与开发工具集成。它的 GitHub Actions 工作流可以响应问题和拉取请求中的 @claude 提及，Claude Code 现在支持用于特定任务工作流的专门子智能体。

Codex CLI 将 OpenAI 的编码智能体带入终端，GitHub Copilot CLI 现在被定位为具有更高自主性模式的终端原生智能体，而 Google 的 Gemini CLI 为 Gemini Code Assist 智能体模式提供动力。终端不再只是一个 shell，它成为了智能体的操作系统。

AI 原生编辑器进一步推进了这一逻辑。Cursor 将自己定位为 AI 编辑器和编码智能体。Cursor Agent 可以完成复杂任务、运行终端命令和编辑代码，而 Cloud Agents 远程运行，Automations 可以按时间表或事件触发智能体工作。

Windsurf 的 Cascade 结合了规划、代码编辑、记忆和工作流。编辑器不再仅仅是人类编写代码的地方，它成为了一个协调层，人类在其中监督、重定向并与智能体协作。

### 指令和集成成为基础设施

一旦智能体能够行动，组织发现了一个新问题：你如何让它们像你的团队一样行动？这就是为什么指令文件和互操作性协议变得至关重要。

Anthropic 在 2024 年底引入了 MCP，作为 AI 应用连接外部工具和数据源的开放标准。同时，AGENTS.md 等仓库指令文件为编码智能体提供了一个可预测的地方来查找设置步骤、测试命令、架构指导和审查期望。

OpenAI 的文档说 Codex 在做任何工作之前会读取 AGENTS.md 文件。Anthropic 的 CLAUDE.md 文件和自动记忆给 Claude 持久化的项目上下文。GitHub 支持仓库和组织级别的自定义指令，而 Cursor 暴露了持久化的 Rules。Prompt 工程已经变得更像基础设施。

这在历史上很重要，因为它标志着另一个概念转变。在早期的 Copilot 时代，prompt 大多是短暂的：一个注释、一个函数名、一个光标位置。在智能体时代，持久的指令与短暂的请求同样重要。

团队现在将设置命令、测试规则、代码风格、升级路径和审查标准编码在与仓库一起传播的文件中。这与"预测下一行"是非常不同的世界。它更接近于给新队友一本操作手册。

### 历史真正告诉我们什么

描述这段历史最清晰的方式不是自动补全变得更聪明了，而是软件工程的系统性分解为机器可操作的层。首先是代码模型，然后是行内生成，然后是对话，然后是代码库感知，然后是工具使用，然后是后台执行，然后是持久记忆，然后是审查和验证层。每一个突破都解决了前一个突破造成的瓶颈。

我们开始时是教机器预测代码。暂时结束时，我们围绕能够接受目标、导航系统并产生工作变更的机器来重新组织软件工程。
