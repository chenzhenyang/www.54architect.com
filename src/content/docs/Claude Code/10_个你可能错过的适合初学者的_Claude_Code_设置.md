10 个你可能错过的适合初学者的 Claude Code 设置

受 @bcherny 关于“和 Claude 一起学习”的帖子启发。以下是我希望早点知道的一些设置。

1. 输出样式（最容易被忽略！）

/config →输出样式

- 解释性说明：Claude解释了每一项改变背后的“原因”。
学习方式：留下待办事项供你自行编写代码，边做边学。

我一开始都没意识到它藏在 /config 目录下。

2. CLAUDE.md — 项目记忆

关键要点：不要自己写。让Claude写，然后反复修改。

首次尝试：“生成一个 CLAUDE.md 文件，总结该项目的技术栈和规范”。

之后：每当 Claude 犯错时，就说“将此规则添加到 CLAUDE.md 中”。

随着时间的推移，这个文件会变得越来越智能。只需将其放在项目根目录下，它就会自动运行。

3. 自定义斜杠命令

你知道 /help 和 /config 吗？你可以创建自己的帮助和配置命令。

与其每次都输入“请编写提交信息，采用标准的提交格式，英文，简洁……”——

创建 ~/.claude/commands/commit.md 文件，并在其中添加您的提示符。

现在 /commit = 整个提示符。

4. 模型切换

/模型

Sonnet：速度快，适合日常编码
Opus：更智能、更有效地应对复杂的架构决策

5. 自动更新通道

/config →自动更新通道→稳定版

稳定版发布会延迟几天，但会跳过有缺陷的版本。

初学者：选择稳定、少有意外的情况。

6. /status — 查看您的配额

只需输入 /status

查看您剩余的代币数量、当前模型以及本次对话的成本。

如果您有使用量限制，则此设备必不可少。

7. /compact — 压缩对话

Claude聊天太久之后是不是变笨了？输入 /compact

它压缩对话历史记录，保留重要内容，恢复回复质量。

8. /doctor — 诊断问题

Claude行为异常？先运行 /doctor 命令。

自动检查您的配置是否存在问题。

9. /init — 理解不熟悉的代码

刚克隆了一个GitHub仓库？还是继承了别人的代码库？

输入 /init — Claude 会扫描整个项目并带你了解它的功能、如何运行它。

处理不熟悉的代码的第一步。

10. 自定义输出样式

想让Claude做点别的吗？比如技术写作助理、代码审查导师、框架讲师？

/output-style:new 我想要一种能够教授 Next.js 最佳实践的样式

Claude会为你生成。随时可以切换。

我对初学者的建议是：首先将输出样式更改为解释性样式，然后让 Claude 为你的项目生成一个 CLAUDE.md 文件。

学习曲线瞬间变得平缓。
