# 线性流程

1 你刚 clone 一个仓库
2 AI 帮你写了一堆代码（Vibe Coding）
3 新人 onboarding
4 做技术分享

## 一、标准 Linear Walkthrough Prompt 模板

```markdown
Your task is to produce a linear walkthrough of this repository.

Goal:
Create a step-by-step explanation of how this project works.

Instructions:

1. Explore the repository structure first.

2. Identify the main entry points of the application.

3. Determine the execution flow of the system:
   - initialization
   - configuration
   - main logic
   - external integrations
   - output or API behavior

4. Produce a linear walkthrough that explains the system step by step.

Important rules:

- Never copy code manually.
- Always extract code using shell commands such as:
  grep
  sed
  cat
  head
  tail

- For each step:
  1. Explain the concept
  2. Show the relevant code
  3. Explain what that code does

Output format:

Create a Markdown document called:

walkthrough.md

Structure:

# Project Walkthrough

## 1. Repository Structure

Explain the folder structure.

## 2. Entry Point

Explain where execution begins.

## 3. Initialization

Explain how configuration and setup works.

## 4. Core Logic

Explain the main logic of the system.

## 5. Key Components

Explain important modules.

## 6. Data Flow

Explain how data moves through the system.

## 7. Summary

Summarize the architecture.

Make the walkthrough readable for an engineer who has never seen this project before.
```

二、加强版 Prompt（作者实践级）
如果你想让 Agent生成的文档更像技术文档，建议用这个版本：

```markdown
Read the source code of this repository and create a structured linear walkthrough.

Your job is to help an engineer understand how the system works.

Workflow:

1. Explore the repository
2. Identify the main entry point
3. Trace the execution flow
4. Identify major modules
5. Document how data flows through the system

For every step:

- Add a textual explanation
- Extract the exact code snippet using shell commands
- Explain the role of the snippet

Do NOT manually copy code.

Always extract code using commands like:

grep
sed
awk
cat

The walkthrough should include:

1. Repository overview
2. Execution entry point
3. Initialization logic
4. Core architecture
5. Important modules
6. External integrations
7. Data flow
8. Error handling
9. Summary

Write the output to:

walkthrough.md

The document should be readable, structured, and detailed.
```

## Self-Explaining Repository Agent

下面是一个工程化程度更高的方案：Self-Explaining Repository Agent（自解释代码库 Agent）。目标是让任何仓库在极少人工参与的情况下自动生成架构文档、线性 walkthrough、依赖图、数据流图以及关键模块说明。整体设计可嵌入 CI，也可以本地运行。

```markdown
Your task is to analyze this repository and generate a complete technical documentation set.

Goals:

1. Understand repository structure
2. Identify entry points
3. Trace execution flow
4. Analyze modules
5. Extract key code snippets
6. Generate architecture diagrams
7. Produce a linear walkthrough

Rules:

Never manually copy code.

Always extract code using shell commands:

grep
sed
cat
head
tail

Tasks:

Phase 1
Analyze repository structure.

Output:
docs/repository-structure.md

Phase 2
Identify entry points.

Output:
docs/entrypoints.md

Phase 3
Trace execution flow.

Output:
docs/execution-flow.md

Phase 4
Analyze modules.

Output:
docs/modules.md

Phase 5
Describe data flow.

Output:
docs/data-flow.md

Phase 6
Generate diagrams using Mermaid.

Output:
docs/diagrams/*.mmd

Phase 7
Create a full linear walkthrough.

Output:
docs/walkthrough.md

The documentation should allow a new engineer to fully understand the system.
```

标准工程实践：
代码库必须包含：

```shell
/docs
/architecture
/walkthrough
/diagrams
```

并由 Agent自动维护。
这意味着：
代码库将变成自解释系统。
